ЭТАП 1. ПРОЕКТИРОВАНИЕ И РЕАЛИЗАЦИЯ СЕРВЕРНОЙ ЧАСТИ ПРИЛОЖЕНИЯ

1.1 Постановка задачи
---------------------

На начальном этапе практики требовалось спроектировать и реализовать серверную
часть приложения: REST API для управления пользователями и проектами, слой
работы с данными и систему аутентификации на основе токенов.

1.2 Архитектура сервера
-----------------------

Серверная часть реализована на Node.js с использованием фреймворка Express.js.
Приложение разделено на три логических уровня:

— Маршруты (routes) — точки входа API, обрабатывающие HTTP-запросы:
  /api/auth (регистрация, вход, выход, получение текущего пользователя),
  /api/projects (CRUD-операции над проектами),
  /api/users (обновление профиля и пароля).

— Слой доступа к данным (src/db.js) — абстракция над файловым хранилищем.
  Все операции чтения и записи проходят через три функции:
  readDb() — читает и разбирает JSON-файл,
  writeDb(db) — сериализует объект и записывает файл целиком,
  updateDb(mutator) — атомарная операция: read → mutate → write.

— Хранилище данных — файл server/data/db.json, содержащий три коллекции:
  users, sessions, projects.

Выбор JSON-файла в качестве хранилища обусловлен учебным характером проекта:
нет зависимостей от внешних СУБД, хранилище переносимо, данные читаемы
в любом текстовом редакторе. Для продуктивного использования предполагается
миграция на PostgreSQL.

1.3 Система аутентификации
--------------------------

Аутентификация реализована на основе Bearer-токенов. При успешном входе или
регистрации сервер генерирует уникальный токен через crypto.randomUUID()
и записывает в коллекцию sessions с полем expiresAt (TTL 7 дней). Клиент
хранит токен в localStorage и передаёт его в заголовке Authorization: Bearer
при каждом запросе.

Для защиты паролей применён алгоритм scrypt — функция формирования ключа
(KDF), специально разработанная для замедления перебора. При регистрации
генерируется случайная соль (16 байт), к паролю применяется scryptSync(password,
salt, 64), результат сохраняется в виде строки «salt_hex:hash_hex». При входе
хеш вычисляется повторно с той же солью и сравнивается с хранимым значением
через crypto.timingSafeEqual — функцию сравнения с постоянным временем
выполнения, исключающую timing-атаки.

Дополнительно реализована функция cleanExpiredSessions(), вызываемая при
каждом старте сервера и удаляющая записи с истёкшим TTL.

1.4 Структура данных проекта
-----------------------------

Центральный объект системы — Project — содержит данные всех шести ролей:
scriptText и scriptParams (сценарий), directorNotes и storyboard (режиссёрская),
bodyMarkers + bodySilhouettes (костюмы и визаж), markers (монтаж и звук),
а также mediaFiles, documents, comments.

Маркер на таймлайне хранит: time (секунды), tabId (роль), color, title,
comment. Это позволяет фильтровать маркеры по вкладке: каждый специалист
видит только свои метки, не перегруженные данными коллег.

Сервер обеспечивает полный цикл работы с данными: регистрация и вход, создание

2.3 Система интернационализации (i18n)
--------------------------------------

Для поддержки нескольких языков разработан собственный механизм перевода
на базе React Context без сторонних библиотек. Система состоит из трёх
компонентов.

Словарь переводов — объект dictionary типа Record<string, { en: string;
zh: string }>. Ключом служит русская строка (базовый язык системы),
значением — переводы на английский и китайский. Такой подход исключает
необходимость отдельных ключей-идентификаторов: в коде компонентов можно
писать t('Удалить проект?') вместо t('common.deleteProject').

Функция подстановки параметров replaceParams поддерживает шаблонные вставки
вида {ключ}:

    const replaceParams = (template, params) => {
      if (!params) return template;
      return Object.entries(params).reduce((acc, [key, value]) => {
        return acc.split(`{${key}}`).join(String(value));
      }, template);
    };

Использование split().join() вместо replace() с регулярным выражением
обеспечивает корректную замену всех вхождений без экранирования специальных
символов в ключах.

Функция перевода t() сначала проверяет текущий язык: если русский —
возвращает исходную строку с подстановкой параметров. Иначе ищет перевод
в словаре; при отсутствии ключа возвращает исходную строку (мягкий fallback).

Выбранный язык сохраняется в localStorage и восстанавливается при следующем
запуске. При смене языка обновляется атрибут document.documentElement.lang,
что корректно информирует скринридеры и поисковые системы.

Итого в словаре: более 140 строк, покрывающих весь интерфейс приложения
(навигация, формы, сообщения об ошибках, подсказки, модальные окна).

3.2 Таймлайн и маркерная система
---------------------------------

Таймлайн проекта отображает временну́ю шкалу с маркерами всех ролей. Каждый
маркер привязан к конкретной позиции в секундах и принадлежит одной из шести
вкладок (tabId). При отображении маркеры фильтруются по активной вкладке —
монтажёр видит только свои метки, звукорежиссёр — свои.

Реализованы следующие операции с маркерами:
— добавление маркера кликом по таймлайну с автоматическим вычислением времени
  по позиции клика (offsetX / containerWidth * duration);
— редактирование заголовка, цвета и комментария через инлайн-форму;
— удаление маркера с немедленным обновлением состояния;
— клик по маркеру перематывает виртуальный плеер к соответствующему времени.

Длина таймлайна (timelineDuration) настраивается пользователем. При уменьшении
длины ниже позиции существующих маркеров предусмотрено автоматическое
«зажатие» (clamping): маркеры сдвигаются к новой максимальной позиции.

3.3 Рабочее пространство костюмера и визажиста
----------------------------------------------

Для ролей костюмера и визажиста реализованы анатомические карты — интерактивные
SVG-изображения, на которых расставляются координатные маркеры.

Карта тела (вкладка «Костюмы») — силуэт человека в полный рост. Каждый
маркер Body Marker хранит: координаты клика x, y (в процентах от размеров
SVG), зону тела bodyPart, заголовок, описание, изображения (base64),
комментарии и привязку к персонажу (personId).

Карта лица (вкладка «Визаж») — схема лица с зонами (лоб, глаза, нос, щёки,
губы, подбородок). Клик по SVG-зоне открывает форму создания маркера;
опубликованные маркеры отображаются в виде точек поверх силуэта.

Список персонажей (bodySilhouettes) синхронизирован с параметром сценария
actorsCount: при изменении числа актёров массив автоматически расширяется
или сокращается, сохраняя данные существующих записей.

4.1 Постановка задачи
---------------------

обеспечения работоспособности приложения при потере интернет-соединения.

4.2 Укрепление безопасности сервера
------------------------------------

Добавлены две ключевые меры защиты серверной части.

Middleware helmet устанавливает набор HTTP-заголовков безопасности:
Content-Security-Policy, X-Frame-Options, X-Content-Type-Options и другие.
Это стандартная мера защиты от XSS, кликджекинга и сниффинга типов контента.

Ограничение частоты запросов (rate limiting) через express-rate-limit:
не более 100 запросов с одного IP-адреса за 15-минутное окно. При превышении
лимита сервер возвращает статус 429 Too Many Requests. Это защищает API от
перебора паролей и DDoS-атак низкой интенсивности.

Дополнительно разрешена проблема конфликта портов: на macOS порт 5000 занят
службой AirPlay Receiver. Сервер переведён на порт 5001 во всех конфигурационных
файлах.

4.3 Офлайн-режим
----------------

Механизм офлайн-режима реализован в AuthContext — глобальном контексте
аутентификации. Логика разделена на три сценария.

Нормальная работа (сервер доступен): при инициализации приложения выполняется
запрос GET /api/auth/me с сохранённым токеном. При успехе данные пользователя
обновляются из ответа сервера.

Потеря соединения (сетевая ошибка): функция isNetworkError() определяет тип
исключения — если это TypeError с сообщением «fetch» или NetworkError, значит
сервер недоступен. В этом случае пользователь не выбрасывается на страницу входа:
данные загружаются из localStorage (ключ synchub_user), устанавливается флаг
isOffline = true.

Вход в офлайн-режим напрямую: если при попытке войти сервер недоступен,
создаётся локальный объект пользователя с id = 'local_' + Date.now(),
токен устанавливается в строку 'local'. При последующих запусках наличие
токена 'local' сигнализирует о том, что нужно работать из кеша.

Состояние isOffline передаётся через контекст во все компоненты. Компонент
OfflineBanner отображает уведомительную полосу вверху экрана при isOffline
=== true, информируя пользователя о том, что изменения сохраняются локально.

4.4 Санитизация HTML-контента
------------------------------

При работе с текстом сценария (contenteditable-поле) пользователь может вставить
текст из внешних источников с RTL-управляющими символами (U+200F, U+202E и др.)
или атрибутами dir="rtl". Такие вставки способны визуально исказить интерфейс,
изменив направление набора текста.

Реализована функция sanitizeScriptHtml, применяющая четыре последовательных
regex-преобразования:
1. удаление Unicode bidi-управляющих символов (диапазоны U+200E–U+200F,
   U+202A–U+202E, U+2066–U+2069);

6.1 Постановка задачи

6.2 Раскадровка (Storyboard Grid)
----------------------------------

Вкладка режиссёра получила интерактивную таблицу раскадровки. Строки таблицы
соответствуют локациям, столбцы — кадрам. Количество столбцов настраивается
(по умолчанию 4). Каждая ячейка представляет отдельный кадр и содержит:
изображение (загружается через drag-and-drop или кнопку выбора файла),
тип кадра, текстовое описание.

Клик по ячейке открывает модальное окно редактирования. Изображения
сжимаются на стороне клиента через Canvas API перед сохранением (функция
compressImage): вычисляется коэффициент масштабирования, сохраняются пропорции,
результат кодируется в JPEG с качеством 0.82. Это позволяет хранить
изображения в JSON-базе без выделенного файлового сервера.

Названия локаций редактируются прямо в шапке строки (inline-edit). Кнопки
добавления и удаления строк управляют одновременно таблицей и параметром
scriptParams.locationsCount — данные остаются согласованными.

Для поддержки изображений в JSON-базе лимит тела запроса на сервере увеличен
с 2 МБ до 10 МБ.

6.4 Межвкладочная привязка данных
----------------------------------

Реализована двусторонняя синхронизация данных между вкладками:

scriptParams.actorsCount ↔ bodySilhouettes
При изменении числа актёров в форме сценариста массив персонажей-силуэтов
(используемый во вкладках «Костюмы» и «Визаж») автоматически расширяется
или сокращается. При уменьшении число проверяется: если у удаляемого
персонажа есть маркеры — выводится предупреждение. Существующие данные
персонажей при расширении массива не перезаписываются.

scriptParams.locationsCount ↔ storyboard.locationNames
При изменении числа локаций в форме сценариста массив строк таблицы
раскадровки синхронно добавляет или удаляет строки. При удалении строки
проверяется наличие данных в ячейках — непустые строки не удаляются без
явного подтверждения.

7.2 Визуальная концепция
------------------------

Разработана концепция «PRODUCTION SLATE» — интерфейс, стилистически
апеллирующий к профессиональному кино. Ключевые элементы:

— Живой счётчик тайм-кода (hh:mm:ss:00) на базе setInterval и useState;
  инкрементируется каждую секунду с момента загрузки страницы.
— Индикатор REC с пульсирующей красной точкой.
— Wireframe-текст «SYNCHUB» на фоне hero-секции: -webkit-text-stroke при
  color: transparent создаёт контурные буквы.
— Диагональный срез нижней границы hero через clip-path: polygon().
— Ячеистая сетка карточек с 1px-разделителями (gap: 1px на родителе,
  background на ячейках).
— Секционные «номера-этажи» из крупных прозрачных цифр на фоне (01–07).

7.3 CSS-анимации (@keyframes)
------------------------------

Реализованы четыре именованных анимации:

bg-text-drift (24s, infinite) — фоновый wireframe-текст медленно дрейфует
по нелинейной траектории: translateY(-50% ± 22px) + translateX(± 12px).
Несимметричные смещения создают органичное движение без монотонности.

headline-glitch (11s, infinite) — глитч-эффект на главном заголовке.
Срабатывает однократно в диапазоне 88–93% цикла: clip-path обрезает текст
до горизонтальных полос, transform: skewX() наклоняет их в разные стороны.
Визуально имитирует артефакт видеосигнала.

pill-slide-in (0.5s, once) — пилюли-роли появляются со смещением
translateX(-18px) → 0, с stagger-задержками 0.2s–0.8s через :nth-child.

mockup-pulse (6s, infinite) — рамка иллюстрации интерфейса «дышит»
фиолетовым box-shadow с периодом 6 секунд.

Бегущая строка-тикер: массив TICKER_ITEMS трижды дублируется в JSX, CSS-анимация
translateX(-33.333%) за один цикл создаёт бесшовную бесконечную петлю.

7.4 Скролл-анимации (IntersectionObserver)
-------------------------------------------

Для блоков, видимых ниже fold, реализована система анимаций появления.
IntersectionObserver с порогом 0.07 отслеживает все элементы с классом .anim.
При пересечении добавляется класс .is-visible, активирующий CSS-переходы.

Таймлайн-рейка раздела «Как начать»: ширина линии анимируется от 0 до 100%
за 1.8s с cubic-bezier(0.2, 0, 0.1, 1). Точки на рейке появляются последовательно
с задержками 0.3s, 0.85s, 1.35s, 1.8s.

7.5 Компонент анимированного счётчика (CountUp)
------------------------------------------------

Для секции статистики разработан React-компонент CountUp. Принимает три
параметра: target (целевое значение как строка), active (флаг запуска),
delay (задержка для stagger-эффекта).

Анимационный цикл на requestAnimationFrame использует кубическую easing-функцию
eased = 1 - (1-p)³, где p — линейный прогресс 0→1. Это даёт быстрый старт
и плавное замедление в конце. Длительность адаптивна: min(1300, 500 + num * 18)
— для числа «6» это 608 мс, для «100» — ограничено 1300 мс.

Строки с нечисловыми значениями («∞») определяются через регулярное выражение
и отображаются без анимации. Флаг done на useRef исключает повторный запуск
при ре-рендерах.

Отдельный IntersectionObserver с порогом 0.25 активирует счётчики при
появлении секции статистики в viewport и сразу отключается (disconnect),
поскольку анимация однократна.

7.6 Исправление сетки (grid-column: 1 / -1)
--------------------------------------------

В процессе тестирования обнаружена проблема: шестая карточка (Звукорежиссёр)
занимала одну колонку из трёх, оставляя две пустых ячейки. Решение: класс
.land-role-card--full { grid-column: 1 / -1 } растягивает карточку от первой
до последней линии сетки независимо от числа колонок. Класс назначается
через условие i === ROLES.length - 1 в JSX.
