- [x] 3 языка интерфейса (RU / EN / ZH)

- [x] Таймлайн с маркерами
- [x] Канбан-доска задач
- [x] Раскадровка
- [x] Двухпанельные интерфейсы Костюмы и Визаж

- [x] Swagger UI на `/api/docs`

## Phase 1 — Стабилизация ядра

**Цель:** довести существующий функционал до production-качества, закрыть UX-разрывы, ввести строгий ролевой контроль.

### Сделано

- [x] **Production Pipeline**: 5 фаз с визуальной полосой прогресса и условиями перехода
- [x] **Stage gate**: на фазе `development` редактируют только сценарист и продюсер до блокировки первой сцены
- [x] **Scene-driven storyboard**: раскадровка привязана к сценам, профессиональные сокращения планов
- [x] **Cross-tab character sync**: персонажи из сцен → dropdown в Костюмах и Визаже
- [x] **Сворачиваемый header** с сохранением состояния
- [x] **Modal overhaul**: непрозрачные оверлеи, гарантированная видимость без внешнего скролла
- [x] **Emoji removal**: полная замена на Lucide-иконки во всём UI
- [x] **Audio playback**: HTML5-плеер подключён к таймлайну
- [x] **Dark-mode color audit**: устранены конфликты `white-on-white`

### В работе

- [~] Согласованность типографики и spacing между вкладками
- [~] Полная локализация всех новых строк после рефакторинга
- [~] Документация компонентов (`docs/components.md`)

### Запланировано

- [ ] **WCAG 2.1 AA контраст-аудит** в обеих темах с автоматизированной проверкой (axe-core)
- [ ] **Keyboard navigation**: полный обход по Tab, escape-handlers для всех модалок, `aria-live` для тостов
- [ ] **Skeleton loaders** вместо общего спиннера на странице проекта
- [ ] **Error boundaries на уровне вкладок**: падение одной вкладки не убивает приложение
- [ ] **Серверная валидация согласована с клиентской** — единая схема через Zod или JSON Schema
- [ ] **Унифицировать формы**: все модалки на одном `useForm` (валидация, ошибки, dirty-state)
- [ ] **Toast queue management**: ограничение количества одновременных, группировка повторов
- [ ] **Confirm modals** заменить на `Modal` компонент (сейчас часть использует `window.confirm`)
- [ ] **Empty states** для всех списков с CTA-кнопкой
- [ ] **Bulk actions** в Менеджере: массовое изменение статуса задач
- [ ] **Project archive**: вместо удаления — архивирование с возможностью восстановления

**Целевая дата завершения:** Q3 2026.

## Phase 2 — Реальное сотрудничество

**Цель:** превратить SyncHub в инструмент реальной командной работы — присутствие, синхронизация, история.

### Realtime

- [ ] **WebSocket-сервер** на базе `ws` или `socket.io`
- [ ] **Presence**: видимость активных участников в проекте, отображение «кто что редактирует»
- [ ] **Optimistic updates** с автоматическим разрешением конфликтов (last-write-wins для простых полей, CRDT для сценария)
- [ ] **Realtime canban**: drag-and-drop задач виден всем участникам мгновенно
- [ ] **Cursor sharing** на таймлайне: видимость позиции коллег
- [ ] **Typing indicators** в комментариях

### Версионирование

- [ ] **История изменений сценария** с возможностью отката
- [ ] **Diff-просмотр** двух версий сцены
- [ ] **Snapshots проекта** перед переходом фазы (rollback при ошибке)
- [ ] **Audit log**: кто, что и когда менял — для разрешения споров

### Уведомления

- [ ] **In-app notifications**: дедлайны, упоминания, изменения статусов
- [ ] **Email-дайджест** ежедневный/еженедельный
- [ ] **Push-уведомления** (Web Push API)
- [ ] **Telegram-бот** для команды: уведомления о смене фазы, новые задачи

### Комментарии 2.0

- [ ] **@упоминания** с автокомплитом по участникам
- [ ] **Reactions** (как в Slack)
- [ ] **Threads**: ответы группируются
- [ ] **Resolve flow**: только автор задачи или владелец может закрыть

**Целевая дата:** Q4 2026 — Q1 2027.

## Phase 3 — Мобильное приложение и offline-first

**Цель:** работа на площадке без интернета.

### Offline-first

- [ ] **Service Worker** для кеширования assets и API-ответов
- [ ] **IndexedDB** для локальной БД проекта
- [ ] **Sync engine**: очередь операций при потере связи, автоматическая отправка при восстановлении
- [ ] **Conflict resolution UI** для случаев, когда коллега менял те же данные оффлайн
- [ ] **PWA**: установка как приложение, иконка на главный экран

### Нативные мобильные приложения

- [ ] **iOS / Android** через React Native или Capacitor
- [ ] **Камера интеграция**: фото для раскадровки и референсов прямо из приложения
- [ ] **GPS**: автоматическая отметка локации съёмочного дня
- [ ] **Push-уведомления**
- [ ] **Биометрический вход** (Face ID / Touch ID)
- [ ] **Apple Pencil**: рисование раскадровки на iPad

### Площадка-режим

- [ ] **Shooting day checklist**: открыть день → видеть только сцены и задачи этого дня
- [ ] **Quick capture**: одна кнопка для отметки «снято», голосовая заметка
- [ ] **Walkie-talkie mode**: push-to-talk внутри команды
- [ ] **Call sheet генерация**: PDF с участниками, временем, локацией, оборудованием

**Целевая дата:** Q2 2027.

## Phase 4 — AI-ассистент

**Цель:** автоматизация рутинных операций с помощью LLM и мультимодальных моделей.

### Сценарий

- [ ] **Парсинг PDF/DOCX сценария**: автоматическое выделение сцен (ИНТ/НАТ, локация, время суток), персонажей, реплик
- [ ] **Сценарный консультант**: предложения по структуре, поиск сюжетных дыр
- [ ] **Перевод сценария** на другие языки с сохранением форматирования
- [ ] **Озвучка реплик** для предпроизводственного прослушивания

### Раскадровка

- [ ] **Text-to-storyboard**: генерация эскизов кадров по описанию сцены
- [ ] **Style-guide**: загрузка референс-стиля → генерация кадров в этой эстетике
- [ ] **Shot recommendation**: AI предлагает тип плана и движение камеры на основе описания

### Костюмы и визаж

- [ ] **Образ по описанию**: «крепкий мужик 50 лет в чёрном пальто» → референсы, бренды, бюджет
- [ ] **Cohesion check**: проверка стилевой согласованности образов в одной сцене
- [ ] **Continuity warnings**: алерт, если костюм/грим персонажа меняется между связанными сценами без сюжетной причины

### Менеджмент

- [ ] **Smart task generation**: при создании сцены — автоматически предлагаются задачи всем отделам
- [ ] **Deadline prediction**: оценка реалистичности дедлайнов на основе истории команды
- [ ] **Бюджет-оценка**: автоматический расчёт примерной стоимости по параметрам сценария
- [ ] **Risk analysis**: AI выделяет потенциально проблемные сцены (погода, опасные эффекты, сложный грим)

### Конфигурация

- [ ] **Подключаемые LLM**: OpenAI, Anthropic, локальные модели через Ollama
- [ ] **Per-project AI budget**: лимиты по токенам
- [ ] **Опт-аут**: возможность полностью отключить AI на уровне проекта

**Целевая дата:** Q3-Q4 2027.

## Phase 6 — Production-релиз

**Цель:** запуск как коммерческого SaaS или open-source-продукта с community.

### Инфраструктура

- [ ] **Multi-tenant архитектура**: изоляция данных между организациями
- [ ] **Object storage** для медиа (S3-совместимое): Cloudflare R2 / Backblaze B2
- [ ] **CDN** для статики и медиа
- [ ] **Horizontal scaling**: stateless API, sticky-sessions через Redis
- [ ] **Database replication**: read-replicas для отчётов
- [ ] **Background job queue**: BullMQ для тяжёлых операций (экспорт, AI)
- [ ] **Monitoring**: Sentry для ошибок, Grafana + Prometheus для метрик
- [ ] **Uptime ≥ 99.9 %**: alerting через PagerDuty

### Безопасность

- [ ] **2FA** (TOTP, WebAuthn / passkeys)
- [ ] **SSO** для команд (SAML / OIDC)
- [ ] **Audit log** с экспортом для compliance
- [ ] **GDPR**: запрос на удаление данных, экспорт всех персональных данных
- [ ] **End-to-end шифрование** документов и сценариев (опционально)
- [ ] **Регулярный pentest**

### Биллинг

- [ ] **Тарифы**: Free (1 проект), Pro (команда до 10), Studio (без лимитов)
- [ ] **Stripe** интеграция
- [ ] **Самостоятельный хостинг** (self-hosted edition) с pay-once лицензией
- [ ] **Образовательная лицензия** бесплатно для студентов и преподавателей

### Сообщество

- [ ] **Документация**: docs.synchub.dev
- [ ] **YouTube канал**: туториалы и case-studies
- [ ] **Discord**: support и обсуждения
- [ ] **Open-source ядро**: AGPL для community-edition

**Целевая дата:** 2028-2029.

## Технический долг

Известные проблемы и улучшения, не привязанные к конкретной фазе.

### Архитектура

- [ ] **Project.tsx (2400+ строк)** → разнести по хукам и контекстам:
  - `useProjectData()` — загрузка и сохранение
  - `useTimeline()` — состояние плеера, маркеры
  - `useTaskKanban()` — drag-and-drop, фильтры
  - `ProjectContext` — общие данные для всех вкладок
- [ ] Миграция стилей на CSS Modules или vanilla-extract для type-safety
- [ ] Замена `npm` на `pnpm` для ускорения CI

### Производительность

- [ ] **Виртуализация длинных списков** (задачи, сцены, комментарии) через react-virtual
- [ ] **Code splitting** по маршрутам — сейчас весь bundle ~440 KB
- [ ] **Image optimization**: webp с fallback, lazy loading
- [ ] **API pagination**: списки проектов, задач, комментариев
- [ ] **Database query optimization**: explain analyze на медленных запросах

### Качество кода

- [ ] **ESLint + Prettier** с pre-commit hook (Husky)
- [ ] **Strict null checks** в полном объёме (есть несколько `as any`)
- [ ] **Покрытие тестами**: целевой минимум 60% для server, 40% для critical client-логики
- [ ] **Visual regression testing** через Chromatic или Percy
- [ ] **Bundle size budget** с CI-блокировкой при превышении

### DevOps

- [ ] **Docker-compose** для one-command local dev
- [ ] **Production Dockerfile** для backend
- [ ] **Helm chart** для Kubernetes
- [ ] **Database backups**: ежедневные с retention 30 дней
- [ ] **Staging environment** на пуш в `develop`
- [ ] **Automated dependency updates** через Renovate / Dependabot

## Процесс

### Как мы планируем

1. **Issue → Discussion**: каждая крупная идея сначала обсуждается в GitHub Discussions
2. **RFC**: для архитектурных изменений — pull request с документом в `docs/rfc/`
3. **Milestones**: каждая фаза = milestone с привязанными issues
4. **Release notes**: автоматическая генерация из conventional commits

### Как контрибьютить

См. `CONTRIBUTING.md` (будет создан в Phase 1). Кратко:

1. Fork → feature branch → PR в `develop`
2. CI должен пройти (tsc, build, tests)
3. Code review владельца репозитория
4. Squash merge с conventional commit message
