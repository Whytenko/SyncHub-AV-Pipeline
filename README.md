## О проекте

**SyncHub AV Pipeline** — дипломный проект, развившийся в полноценную production-ready веб-платформу для координации работы съёмочной группы.

Большинство существующих инструментов решают одну узкую задачу: Final Draft для сценария, StudioBinder для раскадровки, Frame.io для монтажа, Asana для задач. Это приводит к расхождению версий, ручному переносу данных между системами и информационному шуму. SyncHub собирает все этапы кино- и видео-производства — **Development → Pre-Production → Production → Post-Production → Delivery** — в едином приложении с жёстким контролем фаз, ролевым доступом и сквозной связью данных между отделами.

### Решаемые проблемы

| Проблема | Решение в SyncHub |
|---|---|
| Сценарист закончил, а отделы уже что-то делают на черновых данных | **Stage gate**: пока сценарист не заблокировал хотя бы одну сцену, остальные отделы read-only |
| Имена персонажей переписываются вручную между костюмами/визажом | **Cross-tab sync**: персонажи из сцен автоматически появляются в выпадающих списках костюмов и образов грима |
| Раскадровка живёт в отрыве от сцен | Раскадровка **привязана к сценам**: количество кадров задаётся сценаристом или режиссёром, профессиональные сокращения планов (ОП, СП, КП, ДТЛ…) |
| Съёмочный календарь делается в Excel | **ShootingCalendar**: сцены распределяются по дням, статус каждого дня (запланирован/идут съёмки/завершён) автоматически перетекает в статус сцен |
| Контроль фаз производства — на словах | **ProductionStageBar** с gate-условиями: переход на следующую фазу разрешён только при выполнении конкретных условий (минимум N заблокированных сцен, все съёмочные дни закрыты и т.д.) |

## Ключевые возможности

### Production Pipeline
- 5 фаз производства с визуальной полосой прогресса и пошаговыми условиями перехода
- Контроль доступа на уровне ролей и фаз: до момента блокировки первой сцены работают только сценарист и продюсер
- Сквозная связь данных: персонажи, сцены, локации и временные метки используются всеми вкладками
- **Per-project роли**: пользователь выбирает свою роль при первом входе в проект — глобальный профиль не влияет на права. Изменить может только владелец проекта.

### Сценарий
- Загрузка файла сценария (PDF, DOCX, PNG, JPG) с drag-and-drop и серверным хранением
- Менеджер сцен: номер, ИНТ/НАТ, ДЕНЬ/НОЧЬ, локация, персонажи (отдельные поля с +/×), хронометраж, страниц, статус, кол-во кадров раскадровки
- Сворачиваемая панель «Полные настройки» с 10 разделами: актёрский состав, масштаб производства, реквизит, эффекты, транспорт, камера, звук, жанр, риски, концепция (50+ параметров)
- 5 статусов сцены: draft → locked → shot → edited → approved

### Режиссёр
- Раскадровка по сценам (а не по локациям): для каждой сцены — управляемое число кадров
- Профессиональные сокращения планов: ДЛ, ОП, СП, ПП, КП, ДТЛ, ПАН, ТИЛТ, ТРК, ПОВ, ВИД, НИЗ
- Кадр содержит изображение, тип плана, описание, длительность в секундах
- Параметры таймлайна (длительность в секундах или MM:SS)
- Заметки режиссёра с возможностью «Поделиться» через буфер обмена

### Костюмер / Визажист
- Двухпанельный интерфейс: слева — список образов, справа — детальная карточка
- Персонаж выбирается из выпадающего списка, заполненного именами из сцен
- **Костюмы**: гардероб с категорией, цветом, материалом, брендом, способом получения (есть / аренда / купить / сшить), ценой; итоговый бюджет; цветовая палитра
- **Визаж**: продукты по 8 зонам (кожа, глаза, брови, губы, скулы, контур, шея, прочее) с color picker и техникой нанесения; время нанесения; заметки по коже
- Загрузка референс-фото с автоматическим сжатием на клиенте

### Монтажёр
- Медиатека с реальной загрузкой видео и аудио на сервер (multer + дисковое хранилище)
- HTML5-плеер с прогресс-баром, синхронизированным с таймлайном проекта
- Документы (PDF, DOCX) с предпросмотром в iframe
- Список комментариев с пометкой «решено», ответами и фильтрацией

### Звукорежиссёр
- Звуковые метки на таймлайне, привязанные к временным позициям
- Модальное окно деталей метки при клике
- Комментарии к звуковой дорожке

### Менеджер / Продюсер
- **Канбан-доска**: 6 колонок (К выполнению / В работе / На проверке / Утверждено / Правки / Заблокировано) с drag-and-drop сменой статуса и сортировкой
- **Список-вид** с фильтрами по статусу и отделу
- **Съёмочный календарь**: распределение сцен по дням, статус дня (planned / shooting / wrapped / postponed)
- **Здоровье проекта**: прогресс-бары по отделам, процент одобренных задач, сводка статусов
- Дедлайны задач: жёлтый бейдж (≤3 дней), красный (просрочено)

### Глобальные функции
- Сворачиваемый header (узкая полоска 32px ⇄ полная высота 80px) для максимизации рабочего пространства
- Тёмная / светлая темы с полным аудитом контраста
- 3 языка интерфейса: Русский, English, 中文
- Адаптивная верстка: десктоп, планшет, мобильная нижняя навигация
- Офлайн-режим: при разрыве соединения приложение работает с кешированными данными и автоматически восстанавливается

## Производственный пайплайн

```
┌───────────────┐   ┌─────────────────┐   ┌─────────────┐   ┌──────────────────┐   ┌──────────┐
│  Development  │ → │ Pre-Production  │ → │ Production  │ → │ Post-Production  │ → │ Delivery │
└───────────────┘   └─────────────────┘   └─────────────┘   └──────────────────┘   └──────────┘
   Сценарий           Раскадровка             Съёмки           Монтаж                 Сдача
   Сцены              Образы                  Календарь        Цветокоррекция         Экспорт
                      Грим                                     Звук
```

**Условия перехода (gates):**

| Фаза → | Условия |
|---|---|
| → Pre-Production | Создана ≥1 сцена; ≥1 сцена в статусе `locked` |
| → Production | Создан ≥1 съёмочный день; все сцены не в `draft` |
| → Post-Production | Все съёмочные дни в статусе `wrapped`/`postponed`; запланированные сцены отмечены как `shot` |
| → Delivery | Все сцены в статусе `approved` |

Переход осуществляется владельцем проекта. Если условие не выполнено — кнопка показывает «Условия не выполнены», открывает модальное окно с детальной разбивкой невыполненных требований.

## Стек

### Frontend
- **React 18** + **TypeScript 5.2** — строгий режим (`strict`, `noUnusedLocals`, `noUnusedParameters`)
- **Vite 5** — сборка, dev-сервер, HMR
- **react-router-dom v6** — клиентский роутинг
- **Context API** — управление состоянием (auth, toast, i18n, hints)
- **lucide-react** — иконки (единая стилистика, никаких emoji в production-интерфейсе)
- **CSS Custom Properties** — без UI-фреймворков, полная управляемость темой

### Backend
- **Node.js ≥20** + **Express 4** — REST API
- **PostgreSQL 16** — основная БД (JSONB для гибких полей)
- **pg** — драйвер с пулом соединений
- **helmet** — security headers
- **express-rate-limit** — защита от брутфорса и DoS
- **multer** — загрузка медиафайлов на диск
- **crypto.scryptSync** — хеширование паролей (соль 16 байт, ключ 64 байта)
- **swagger-jsdoc** + **swagger-ui-express** — интерактивная OpenAPI документация `/api/docs`

### Инструменты
- **GitHub Actions** — CI: typecheck клиента, build, тесты сервера
- **Playwright** — e2e сценарии (включён в зависимости клиента)
- **Node.js built-in test runner** — юнит-тесты сервера

## Быстрый старт

### 1. Клонирование

```bash
git clone https://github.com/Whytenko/SyncHub-AV-Pipeline.git
cd SyncHub-AV-Pipeline
```

### 2. PostgreSQL

```bash
# macOS (Homebrew)
brew install postgresql@16
brew services start postgresql@16

# Linux (Debian/Ubuntu)
sudo apt install postgresql-16
sudo systemctl start postgresql

# Создать БД
createdb synchub
```

### 3. Конфигурация окружения

```bash
cp .env.example .env
# Отредактируйте .env, минимум:
#   DATABASE_URL=postgres://USER:PASSWORD@localhost:5432/synchub
#   PORT=5001
#   ALLOWED_ORIGINS=http://localhost:5173
```

### 4. Сервер

```bash
cd server
npm install
npm run db:setup       # migrate + seed (создаст таблицы и демо-пользователя)
npm run dev            # nodemon, http://localhost:5001
```

### 5. Клиент

```bash
cd client
npm install
npm run dev            # Vite, http://localhost:5173
```

Откройте `http://localhost:5173` и войдите под демо-учёткой (см. ниже).

## Конфигурация

Переменные окружения (`.env` в корне):

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `5001` | Порт Express |
| `DATABASE_URL` | — | Строка подключения PostgreSQL (обязательно) |
| `ALLOWED_ORIGINS` | `http://localhost:5173` | CORS-whitelist, через запятую |
| `SESSION_TTL_DAYS` | `30` | Срок жизни сессии |
| `RATE_LIMIT_AUTH` | `20` | Попыток `/api/auth` за 15 минут |
| `RATE_LIMIT_API` | `120` | Запросов API за минуту |
| `VITE_API_URL` | автоопределение | URL сервера для клиента (только если фронт и бэк на разных доменах) |

## База данных и миграции

Миграции — последовательные SQL-файлы в `server/migrations/`. Применение идемпотентно (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`):

```bash
cd server
npm run migrate    # применяет все *.sql по алфавиту
npm run seed       # вставляет демо-пользователя (idempotent)
npm run db:setup   # = migrate + seed
```

### Основные таблицы

| Таблица | Назначение |
|---|---|
| `users` | Учётки, пароли (scrypt-хеш), профиль |
| `sessions` | Активные сессии с TTL, CASCADE при удалении пользователя |
| `projects` | Проекты: участники, сцены, задачи, медиа, документы, раскадровка, фаза производства, съёмочные дни — гибкие поля JSONB |

Индекс `projects_stage_idx` ускоряет фильтрацию по фазе производства.

## API

Полная интерактивная документация: **`http://localhost:5001/api/docs`** (Swagger UI).

### Аутентификация

| Метод | Маршрут | Описание |
|---|---|---|
| `POST` | `/api/auth/register` | Регистрация (никнейм, пароль, опционально имя/роль) |
| `POST` | `/api/auth/login` | Получить session token |
| `GET` | `/api/auth/me` | Текущий пользователь |
| `POST` | `/api/auth/logout` | Завершить сессию |

### Пользователи

| Метод | Маршрут | Описание |
|---|---|---|
| `GET` | `/api/users/me` | Профиль текущего пользователя |
| `PATCH` | `/api/users/me` | Обновить профиль |
| `PATCH` | `/api/users/me/password` | Сменить пароль |
| `GET` | `/api/users/search?q=…` | Поиск участников для добавления в проект |

### Проекты

| Метод | Маршрут | Описание |
|---|---|---|
| `GET` | `/api/projects` | Список проектов пользователя |
| `POST` | `/api/projects` | Создать проект |
| `GET` | `/api/projects/:id` | Получить проект целиком |
| `PATCH` | `/api/projects/:id` | Частичное обновление (любое поле, включая `scenes`, `tasks`, `productionStage`) |
| `DELETE` | `/api/projects/:id` | Удалить проект |
| `GET` | `/api/projects/:id/export` | Экспорт проекта в JSON |
| `PUT` | `/api/projects/:id/role` | Выбрать роль в проекте (одноразово; владелец может переписывать) |

### Участники

| Метод | Маршрут | Описание |

## Безопасность

| Уровень | Меры |
|---|---|
| **Пароли** | `crypto.scryptSync` с N=16384, r=8, p=1; случайная соль 16 байт; хеш 64 байта |
| **Сессии** | Криптостойкие токены (32 байта random), TTL 30 дней, CASCADE при удалении пользователя |
| **Брутфорс** | `express-rate-limit`: 20 попыток на `/api/auth` за 15 минут |
| **DoS** | 120 запросов в минуту на остальные эндпоинты |
| **HTTP-заголовки** | `helmet`: HSTS, X-Content-Type-Options, X-Frame-Options, CSP базовый |
| **CORS** | Whitelist через `ALLOWED_ORIGINS` |
| **Загрузки** | `multer` с лимитом размера, валидация MIME, файлы вне веб-корня |
| **SQL** | Параметризованные запросы (`pg`), никакой конкатенации |
| **Валидация входа** | Чистая функция-валидатор `src/validate.js` с юнит-тестами |
| **Ролевой контроль** | На клиенте — `canEditTab()` по фазе и роли; на сервере — `authRequired` middleware |

## Интернационализация

3 языка: **Русский**, **English**, **中文**.

Реализация — `I18nContext` с функцией `t(key, params?)`. Все строки UI проходят через `t()`. Переключение языка — `Settings` → `Язык`. Выбор сохраняется в `localStorage`.

Серверные сообщения об ошибках возвращаются на языке клиента через заголовок `Accept-Language`.

## Доступность и адаптивность

- **Контраст**: соответствие WCAG 2.1 AA в обеих темах (тёмная и светлая)
- **Клавиатура**: все интерактивные элементы доступны через Tab; видимый focus-ring
- **Семантика**: `<button>` для действий, `<a>` для навигации, `role="dialog"` + `aria-modal` для модалок

- **Touch**: pointer events для timeline scrub, поддержка drag-and-drop на мобильных устройствах

## История изменений

### v7 — Per-project роли, выбор сцен, редизайн карточек (текущая)
- **Per-project роль**: пользователь выбирает свою роль при первом входе в проект, а не из глобального профиля. Эндпоинт `PUT /api/projects/:id/role`, миграция `003_project_roles.sql` с полем `project_roles JSONB`
- **RoleSelectModal**: модальное окно с 7 карточками ролей (иконка + название + описание), цветная подсветка выбранной, безусловная блокировка перевыбора (только владелец может изменить)
- **SceneMultiSelect**: выбор сцен из списка вместо текстового ввода в формах костюмов и грим-образов; автоподнятие сцен с выбранным персонажем; кнопка «Все с этим персонажем (N)»
- **Редизайн карточки сцены**: цветная полоска статуса слева, боксовая таблетка номера, IE/DN бейдж в цвете статуса, кнопки с рамкой вместо emoji, hover-подъём с тенью
- **Скопировать ссылку на проект**: новая кнопка `Link2` заменила Экспорт в шапке (Экспорт переехал в Настройки проекта); работает в свёрнутом и развёрнутом хедере
- **Модалки шире и ниже**: `min(760px, 96vw)` × `min(80dvh, 100dvh-48px)` — типичные формы влезают целиком; `form-row-2col` автоматически использует две колонки
